UI/UX Architectural Review

Where It Is Through the Year

Avid Birder Experience & UI Specification · Date: September 4, 2026 · Author: AGY

1. The Problem: The "Spreadsheet Disconnect"

The underlying database rollups and pipeline (0050 table maintaining 18 latitude bands across 8 continental columns) are fast and mathematically rigorous. However, the current user interface asks the user to act like a statistician decoding a matrix rather than an avid birder exploring a creature's migratory journey.

Friction Point Why It Disorients the User
Abstract Degrees (`40–50°N`) Degrees of latitude do not exist on field maps. In Eastern North America, 40–50°N stretches from Philadelphia/Columbus up past Toronto into rural Ontario and Newfoundland. 10–20°N is Central America. Users are forced into constant mental translation.
Poles-to-Equator Matrix Waste For a temperate bird like Baltimore Oriole, 60–90°N (Arctic tundra and ice pack) and 0–90°S (Southern Hemisphere) are 100% irrelevant. Yet those empty rows take up over half the card's height with hatched lines and slashes.
The "Diagonal Sweep" Rule The UI caption explicitly instructs: "a diagonal sweep means the bird moves with the seasons and a flat band means it stays put." If a chart requires a user manual to explain that a diagonal line means movement, the metaphor fights human intuition.
5 Competing Control Dials Users are greeted by: a month slider, a Play button, a detached floating stats card, World vs. Continent buttons, a Continent dropdown, and an Equal weight vs. By checklists toggle. Statistical weighting options belong in documentation, not primary UI chrome.
Static Cursor Animation The 12 months are already displayed across the horizontal axis. Scrubbing the slider or pressing "Play the year" just moves a rectangular highlight box over static cells. It animates a cursor, not the actual migration of the bird.

2. How Birders Mentally Model a Bird's Year

When an avid birder consults a field guide, their mental checklist is biological and geographic, not numerical:

  • Breeding Season (Summer): Where does it nest? (e.g. Eastern deciduous woods from the Carolinas to the Great Lakes and southern Canada).
  • Wintering Grounds (Non-breeding): Where does it spend the winter? (e.g. canopy of Central American coffee plantations, Caribbean, south Florida).
  • Migration Windows (Spring & Fall): When does it arrive in the spring (late April)? When does it leave in the fall (late August)?
  • Movement Strategy: Is it a Neotropical long-distance migrant, short-distance migrant, or year-round resident?
The Key Realization: A bird's year is a journey with dramatic arrival and departure cliffs. The visualization should immediately highlight this narrative rather than presenting a flat 2D grid.

4. Implementation Roadmap in SvelteKit

These improvements do not require changes to the database migrations (0050) or rollup logic:

  1. Landmark Dictionary (`migration-ribbon.ts`): Map continent columns + latitude bands to real-world regional names (e.g. NAE + 40 -> 'Great Lakes / New England').
  2. Auto-Cropping Range: Filter out bands where a species has 0 reporting frequency, keeping only the occupied slice + 1 padding row.
  3. Seasonal Phase Banner: Render the 4-phase biological ribbon above the month row headers.
  4. Streamlined Controls: Move statistical weighting into the expandable "How these numbers are calculated" drawer and clean up the continent selector.
