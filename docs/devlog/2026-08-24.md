# 2026-08-24

## Daily retry of unresolved species audio

- Fixed the enrichment scanner's real eligibility defect: a species with an
  existing photo and `media_status = 'error'` is unresolved media work, not a
  fully enriched species.
- Changed recurring enrichment scans to retry partial and failed media on the
  next 24-hour pass instead of waiting seven days. The seven-day retry policy
  remains limited to the separate Wikipedia/AI lanes.
- Changed the explicit Admin enrichment scan to select recent media errors
  and partial results immediately, without waiting for the next daily pass.
  Admin media chunks use a separate forced dedup namespace so freshness checks
  and already-queued normal chunks cannot turn the explicit retry into a no-op.
- Removed a second scanner blind spot that discarded media work whenever the
  same species also needed Wikipedia refresh. The independent Wikipedia and
  media jobs are now both queued because the Wikipedia worker does not repair
  audio.
- Updated the Admin explanation and field-guide media design documentation to
  describe the actual retry behavior.
- Added coverage proving that automatic scans select media errors and partial
  results at the daily retry boundary, while an explicit Admin scan selects
  fresh failures and queues a forced `enrich_species_media` job under a
  separate dedup key.
- Added a 15-minute alignment margin to the 24-hour media retry predicate so a
  failure stamped shortly after one daily scan cannot miss the next scan and
  wait nearly 48 hours.
