### Key Technical Insight
- **Cloud sessions are a different machine with different credentials.**
  - They push through the claude.ai GitHub connector, not your git login.
  - They run in a container without our PG17, so the DB tests can't run.
  - Their transcripts aren't on this Mac.
  - Tells: a ListAgents "cloud" row, a `claude/<session-name>` branch, or a commit `Claude-Session` link you can't find locally. A `git format-patch` paste plus `git am` recovers the work exactly. Verify via the `index` blob hashes.
  - Gaylon will not use cloud sessions again.
- **Any new durable write inside a job unit must be claim-fenced** (`claimFencedQuery`) unless it's an irrevocable external-delivery record. Otherwise an abandoned execution can still change scheduling state.
- **A scheduling stamp written only on success means skipped accounts retry every tick.** So any cheap early-exit checks (devices, home, key) must run *before* upstream API calls.
- **`vi.mock(path, importOriginal)` wrapping one export in `vi.fn(real)`** makes a real helper observable without changing behavior. This is how the test pins which writes are fenced.
