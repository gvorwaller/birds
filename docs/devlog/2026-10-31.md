Plan: `docs/2026-10-31-taxonomy-sources-rematch-plan-CC.md`. CODEX1's plan review gave 3 P2 and 2 P3, all incorporated (revision 2).

**Built:**
- **Former names.** `resolveMatches` (pure) falls back to eBird's former names from `taxonomy_backup_rows`, and only when nothing today has the name.
  - Every backup holding the name is evidence. Each is followed one step into today: still a species, or now an issf/form whose species is reported as a lump.
  - Exactly one surviving species gives a match. None gives no match. Mixed evidence is ambiguous, which covers name reuse across years and splits.
  - `deriveSpecies` reads today's taxonomy once, for both match passes.
- **Migration 0100.**
  - `match_reason` gains `former_name`.
  - `taxonomy_source_rematches` / `_baseline` / `_changes`.
  - The baseline is copied with the before-sync backup, or just before a re-match when a run has none (run 1). The diff is always baseline → now, so a replay or an earlier Sources re-match records the same thing.
  - `places` counts the pair's own raw rows.
- **The run's finish step.** It re-matches each active source, one claim-fenced transaction per source with the source lock, before photo matches and families.
- **"Re-match sources"** on the newest done run, for run 1. It takes the run-admission lock that `startOrResumeRun` also takes, so no newer run can start underneath it.
- **Admin → Taxonomy "Other sources":** per-source counts, the baseline named, every changed taxon, and a full-load link to the source's Unmatched taxa, which opens via `?unmatched=`.
- **Admin → Sources:** "matched by a scientific name eBird used before; eBird now calls it *X*".
- **Help and About:** text updated.
