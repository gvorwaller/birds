## Home remembers the last search, per account (td-9304cd)

- Owner, after td-8e21b8 shipped: going back to Home reverted to the saved home. Decided: remember the last Home search per signed-in account, on the server so it works across devices. It covers a typed place or map point plus Within and Window, and lasts until Reset home defaults. Saving a new home in Settings also forgets it.
- Migration `0079_home_search`: one row per account (`users.id`, ON DELETE CASCADE). A NULL part means the default, so later changes to the Settings radius still show through.
- Writes happen only in Home's POST actions `?/search` and `?/reset` (enhanced; 303 to the shareable GET URL; native POST without JS).
  - `search` resolves a typed place once and redirects with pin params, so the GET never geocodes it again. An unfound place is not remembered.
  - The loader only reads, and only when none of place/dist/back/lat/lng/pin is in the URL. Back, old links and other tabs display without overwriting.
- On the saved home the place box is empty, with the home's name as a "(saved home)" placeholder, so a Within-only change can't geocode the home label.
- Reset keeps the Window when the account has a saved home. Without one it is "Clear this search" and forgets everything; the server decides from the stored home.
- Settings `save_home` forgets the row in the same statement.
- Viewers: `isHomeSearchRequest` allows exactly the first actions `/search` and `/reset` on `/` through the hooks viewer guard. Searches stay on the viewer's own account.
- CODEX1, 5 rounds at high effort:
  - P1: Within-only change geocoded the home label.
  - P2: GET loads wrote, so Back and old links overwrote the search.
  - P2: no Reset without a saved home.
  - P1: viewer POSTs blocked by hooks. Direct action tests had bypassed `handle`; now tested through it.
  - P2: no-home Window-only search had no Clear, and Clear kept the Window.
  - P3: Help/About copy.
  - All fixed; final round clean.
- Evidence:
  - `home-search.test.ts` 18/18 on birds_test (owner/viewer/no-home fixtures, mocked geocoder) and hooks 6/6.
  - Full suite 2424 pass / 1 pre-existing fail / 5 skip.
  - Playwright 72/72 main journey and 14/14 roles probe in Chromium + WebKit.
- WebKit test noise: "Could not load onion" and the GetViewportInfo XHR errors come from the test resizing and leaving a page with an open Google map. They are traced to that step and absent on the unchanged Forecast picker.
- Not tested: iPhone (the form is now POST + redirect).
