## Trips Places API (td-0b9b6e)

Implemented the Birds side of the cross-app Trips import.

Added an authenticated read-only endpoint at `GET /api/internal/trip-places`.
The endpoint is a narrow public-hook carve-out in `src/hooks.server.ts`; it does
not require a Birds browser session, but the route handler still requires
`Authorization: Bearer <BIRDS_TRIPS_API_TOKEN>` before it reads any trip data.

The export helper normalizes owner trip stops into place rows for Trips:

- stable source id: `birds:trip_stop:<id>`
- Birds trip id and trip name
- stop title, coordinates, Google place id, notes, and target count
- optional saved field tip context

The configured export identity can come from the `username` query parameter or
`BIRDS_TRIPS_EXPORT_USERNAME`. Viewer accounts are rejected explicitly so this
integration cannot accidentally export from a read-only account.

### Exchange Logging

Added token-free structured stdout logging for the Trips places export endpoint.
PM2 captures the lines in `/var/log/pm2/birds.out.log` / `.err.log`.

The endpoint emits `[trip-places-export]` JSON lines for:

- `config_error`
- `unauthorized`
- `export_start`
- `export_success`
- `export_config_error`
- `export_error`

When Trips sends `x-trips-import-request-id`, Birds logs the same `request_id`
so one import attempt can be correlated across Trips and Birds logs. Local
smoke proof exported 18 places and matched the Trips request id.
