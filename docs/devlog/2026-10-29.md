**Query speed:**
- The planner's first choice walked every taxon's records, taking 500 ms on prod. Filtering a coordinate box first (a materialized CTE) took 68 ms.
- Migration 0098 swaps the (lat, lon) btree for a GiST index on `point(lon, lat)`. It was measured on birds_test with real Nordland plus 2M synthetic points spread over Norway: 14 ms against 17 ms for a 50 km box (index scan 1.6 ms against 4.5 ms). The gain is small, but it suits a 2-D search.

**Built:**
- **Reader:** `src/lib/server/external-sources/near.ts`, one read snapshot. It runs one aggregate query (box, month, published window via the records' `load_id`, active sources, haversine cut), grouped by place, locality, species and year. The rest is shaped in JS.
- **Nearest-report fallback:** 3× the radius, at least 30 km.
- **Card:** `ExternalNearCard.svelte`. Needs first; per species its places with distance and "in N of M Octobers". The rest of the needs and the seen species sit in `<details>` folds. It also shows the busiest 5 places (Map, plus Add to trip when the place's best report is placed within 1 km) and the municipalities, each linking to "Where and when to look".
- **Forecast loader:** awaits the card with the shell, so it renders without JavaScript; a failure is logged and the card left out. The eBird analysis stream adds the sources that cover eBird's region but have nothing loaded, for a Load button (not for viewers). The page gets the shared `queueExternalLoad` action.
- **Pointer line:** a line in the eBird card links to the card and is never added into the eBird numbers.
- **Help:** one bullet in "Reports from other sources".

**Checks:**
- `near-db.test.ts` has 12 tests. Mutations on the radius cut, the window, seen-per-user and the active filter are each caught. The radius mutation first survived, because a due-north record was already cut by the box; a record in the box's corner, outside the circle, now guards it.
- **Render tests:** 7, covering the card states, wording and list keys. **Loader tests:** 7 (failure isolation, the hint, the pointer).
- **Live check:** real Nordland was loaded into birds_test (own source `xnear-…`). Sandnessjøen in October at 31 mi gives 1,429 / 109 species / 70 needs (fixture user with 39 seen). That equals an independent full-table SQL count and the prod measurement.

- **iOS Simulator (Mobile Safari):** both folds open and close on tap, and "Where in Nordland" navigates. The pass caught a missing fold marker (`display: flex` hides it), now ▸/▾ as on "Where and when to look".
- `npm run check`: 0/0. **Full suite:** 3,306 passed; only the known searchable-select failure.

**CODEX1 (high), round 1: three P2s, all fixed with regressions, each mutation-checked.**
- **F1, duplicate list keys.** Two county-level places with the same name in different counties gave the same Svelte key, which throws on the client. Places now carry a key built from the county or municipality key and the locality, and the card keys by it.
- **F2, box too small.** `boxAround` used dLat/cos(lat), which falls short of the circle's widest longitude; a report at 49.9995 km fell outside a 50 km box. It now uses the exact spherical extent, with full longitude at a pole or across ±180°. Tested against points on the circle every 0.25° in 8 cases.
- **F3, global fallback.** The nearest fallback ran only when every source was empty, so one source's reports hid another's nearest. It now runs per missing active source; a second active source in the fixtures covers it.

**Round 2:** clean. CODEX1 notes that client hydration is not proven by the server-render tests. The browser passes ran with JavaScript on and had no page errors, but the live data had no same-name twins, so the twin case is covered at the reader and the source level only.

CODEX1 ran `td usage --new-session` at startup in both rounds, before it read the no-td rule, and made no other td calls or writes.

**Cleanup:** the live source `xnear-…`, its loads, records, taxa and connector, the fixture user and its seen rows, the connector env file and the dev server are all removed. Migration 0098 stays applied in birds_test, as it is in the repo.
