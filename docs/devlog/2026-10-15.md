**Name-search tightening (td-bdde97), deployed bd76ffc**
- **Owner report:** "Sparrow" in Duval County listed American Kestrel and Shiny Cowbird as "Description or field-note match".
- **Cause:** `searchGuide` always added every species whose Wikipedia text, field craft or tags matched the word.
- **Owner's choice:** hide prose-only matches behind a link and add family matches.
- **Family tier** (tier 5, labelled "Family match"):
  - Takes every species of a single-group family named for the word, matching the family name's last word with full-text search.
  - So Dark-eyed Junco, the towhees and Lark Bunting appear for "sparrow".
  - Families that list several groups ("Hawks, Eagles, and Kites") never match.
- **Prose matches** moved to tier 6. When the query names a bird in the searched scope, they are left out unless `mentions=1`.
  - The scope covers place, family, special interest and tags, but not the All/Need/Seen list.
  - The scope summary says "N more species only mention 'X'… Show them too", with "Hide them" to undo.
  - A word that names no bird in scope ("trill" or "nocturnal" in Florida) searches the prose as before.
- The count of species not yet evaluated for tags follows the same rule. An empty page 1 re-runs the search with mentions included to count what it hides.

### Key Technical Insight
- **"Names a bird" must be judged in the searched scope, not the whole world.** Of the ~11,000 species worldwide, some name contains almost any word ("Trilling Cisticola", "Nocturnal Curassow"). A global check made "trill" a name search and hid every result in Florida.
  - The scope deliberately excludes All/Need/Seen. A personal list split shouldn't turn a name search into a prose search.
- **Same-level window functions see rows after WHERE.** Three nested levels give a different set for each number:
  - `name_query`: after place/interest, before the list filter;
  - the mention count: after the list filter;
  - the total: after the prose gate.
- **Checking a deploy without logging in.** The Chrome extension was not connected, and the auto-mode classifier blocked SSH and session lookups. The public client bundle still verifies a deploy.
  - In SvelteKit's route dictionary, `"/species":[-23]` means node **22**: a negative value is `~n` for routes with a server load. Reading it literally checked the wrong chunk.
  - Match `[^0-9]nodes/22\.`.
  - Saved to memory: `post-deploy-public-bundle-check`.
- **Playwright and SvelteKit client navigation:** after a click, `waitForLoadState('networkidle')` resolves at once. Wait for the URL to change first, or the next `goto` interrupts the pending navigation.
