### What Was Done

  serializes), onUnit/shouldStop/timeBudgetMs hooks, maxFetches unclamped

- **Worker** (`src/worker/` + esbuild bundle): env guards, advisory lock
  0xb15d0001, SIGTERM drain with attempt refund, `birds-worker`
  application_name; PM2 app + deploy gate requires db AND worker ok.
- **Client**: 8 actions across forecast/species/data are thin enqueuers
  returning `{queued}`; old client fetch-loop + 12-per-click county batching

### Key Technical Insight
Cancellation correctness needed FOUR review rounds to pin: it is only safe

cancel that serializes between observation and write. Same lesson applied to
reclaim and requestCancel. READ COMMITTED's EvalPlanQual re-check is what
makes the blocked-UPDATE-re-evaluates pattern sound.
