# 2026-07-30

## Home and Targets consolidation (td-36e446)

Merged the two near-duplicate discovery screens into one. `/` was "Near Me"
(needs around the saved home only); `/targets` was the stronger place-search
experience with notable reports. `/` is now the single canonical Home built on
the Targets implementation, and `/targets` survives only as a redirect.

Plan: `docs/2026-07-30-home-targets-consolidation-plan.md` (written by CODEX,
adversarially reviewed by CC6 — 25 findings, four of them blockers — then
revised before implementation).

### What changed

**Unified Home (`/`)** — the Targets UI renamed, plus the pieces that only
existed on the old Home:

- one loader, one return shape. The old Targets loader returned early when
  there was no location, which would have dropped the At-a-glance and setup
  fields for exactly the brand-new user who needs them.
- `geoTargets()` only. `nearbyNeeds()` had one caller and was removed.
- independent work (user row, gallery, API key, life-list reads, geocode) now
  runs in one `Promise.all` instead of the old serial chain; only the eBird
  fan-out waits on it.
- ported **At a glance** (life-list count, sync time, sync-error badge, linked
  photo count) and the dedicated **Get set up** card for a missing API key —
  Targets had collapsed a missing key into its generic error text.
- the `cached` stale badge now also sits on the needs heading, so a stale list
  with no notable reports still shows it.
- new **Reset home defaults** action: one click back to the saved home _and_ the saved
  radius after searching elsewhere.

**Saved radius.** The saved `users.near_me_radius_km` now drives Home. Absent
_or invalid_ `dist` falls back to the saved value, never to a hard-coded 50 km.
The two routes had incompatible option lists (`8/16/24/40/50` vs `10/25/50`), so
a saved 40 km would have rendered with 10 km selected and silently shrunk the
search on the next submit; `radiusSelectOptionsKm()` guarantees the control
contains the effective value. Radius labels honor the miles/kilometers toggle.

Persistence moved to Settings (new **Search radius** card and `?/save_radius`
action) _before_ the old root POST action was deleted — Settings had no radius
control at all, so removing that action first would have left the column
editable only by SQL and undone commit 8f9a150.

**Compatibility.** `/targets` is a 303 that preserves the whole query string.
`hooks.server.ts` now sends `pathname + search` to Login, so a logged-out
`/targets?place=…&dist=…&back=…` deep link keeps its context through sign-in.
Species return links fall back to `/` (not `/targets`) and label legacy
`/targets…` values "Home" while still honoring them verbatim.

**Species context.** Species links now carry the origin Home is showing
(`lat`/`lng`/`dist`/`loc`), and the species loader centers reports there instead
of always on the saved home. Coordinates and radius are validated on the way in;
a URL cannot push the eBird radius past 1–50 km. The plain saved-home view
deliberately sends no context, so that path keeps its historical 50 km behavior.

**Navigation.** `+layout.svelte` now uses explicit `primaryItems` (Home, Trips,
Photos) and `ownerMenuItems` (Settings) instead of `items.slice(0, 4)` in three
places. Slicing a shortened array would have promoted Settings into the top and
bottom navs and shown viewers a Settings link that the hook bounces back to `/`.

**Viewer-safe copy.** Body text, not just nav: Home's no-location, setup,
empty-life-list and At-a-glance blocks, and the species page's setup line, no
longer point read-only accounts at Settings. Viewers still see the owner's
last sync time, but not the unactionable sync-error badge.

### New pure helpers (all unit-tested)

### Verification (source-level)

- `npx vitest run` on the three new/changed helper files — 30 tests passed
- `npm test` — 13 files / 59 tests passed
- `npm run check` — 404 files, 0 errors / 0 warnings
- `npm run build` — passed
- `npx prettier --check` on every changed file — passed
- `git diff --check` — clean

Prettier caveat: `npm run lint` cannot pass in this repo and never could. No
Prettier config has ever been committed (checked `git log --all` for
`.prettierrc*` / `prettier.config.*`), so `prettier-plugin-svelte` is never
loaded and **no `.svelte` file anywhere in the repo can be parsed** — it fails
identically on files this change never touched. `.ts`/`.md` run on bare defaults
that disagree with the repo's mixed tabs/spaces style, hence 64 pre-existing
"failures" at HEAD. Every changed file here was checked individually against its
HEAD state; the only two still failing (`src/hooks.server.ts`, the V2 design
plan) were already failing before this change and were left alone rather than
introduce a tabs→spaces reformat. Gaylon reviewed this and decided against
adding a Prettier config — no user-visible value for the churn — so this is a
permanent known gap, not a to-do. `npm run check` remains the real gate.

### Browser QA (CODEX, isolated test cluster — APPROVED)

Run against `npm run dev:test` on `127.0.0.1:5178` / `birds_test` (15436). Two
rounds: an initial pass that found three UI defects, and a retest after the fix
round. Approved on the retest. Nothing committed or deployed.

Fixture caveats that shaped the run: `birds_test` is a restored production
snapshot, so its `user_ebird.api_key_enc` is prod ciphertext encrypted under
prod's `EBIRD_KEY_SECRET`, which differs from the local test secret. Every page
that resolves a key therefore returned 500 — confirmed pre-existing by stashing
to `8f9a150`, where `/` and `/targets` both 500 identically. A placeholder key
was substituted, so no live eBird traffic occurred and all lists were served by
the `ebird_cache` fail-soft path; missing notable keys at the 40 km radius were
back-filled and the Blue Hill payload set was cloned onto Bar Harbor's
coordinates (synthetic data — correct for exercising UI, not geographically
real). The 40 km/7-day view was marked fresh and the 14-day window left stale so
both states were reachable.

Round 1 findings, all fixed:

1. **P1 tap target.** `Use my home` was a bare inline link measuring ~103×19 px
   at 390 px portrait, violating `cs.md`'s ≥48 px rule. It also fired after a
   radius-only change while the location was already home, so the label was
   untrue. Renamed to **`↺ Reset home defaults`** (it drops both `place` and
   `dist`, restoring the saved home _and_ the saved radius, keeping `back`), and
   rebuilt as an `inline-flex` control with `min-height: 48px` inside a
   flex-wrap `.loc` row so it wraps to its own line on a phone.
2. **P1 landscape drawer.** At 844×390 the Sign out button sat at top 420 px,
   entirely below the viewport, with no overflow path. Added `overflow-y: auto`
   and `overscroll-behavior: contain` to `.drawer`, plus `flex-shrink: 0` on
   `.drawer-head`. Pre-existing rather than caused by this change — the
   consolidation actually reduced the drawer from 5 nav items to 4 — but it had
   never been exercised at that viewport.
3. **P2 stale copy.** Settings' home-location help still said "the Near Me
   view"; now "the Home view".

Retest evidence: `↺ Reset home defaults` measured 196×48 at 390 portrait,
wrapped inside a 324 px `.loc` with zero overflow, preserved `back=14` in its
href, and on click restored the saved 40 km view and removed itself. Owner
drawer at 844×390: client 390 / scroll 495, overflow auto, Sign out reachable at
top 326 / bottom 374; viewer drawer client 390 / scroll 433, same result, zero
Settings links.

Also confirmed: Home/Trips/Photos nav only; At a glance 222/36; saved 40 km
renders as 25 mi under the miles toggle; a Settings save of 16 km made `/`
default to 9.9 mi, then restored; `/?dist=999` selected 40 km with no malformed
option; `/targets?…` redirected with the query intact; a Bar Harbor search
carried origin+radius into the species link and the species page read "Recent
reports near Bar Harbor" with `← Home` returning to the same filtered URL;
`Show all 2 places` expanded exactly 2 rows; the mi/km toggle updated selector,
summary and expanded distances together. State matrix: viewer saw owner-scoped
222/36 with zero Settings links, no sync-error warning, and `/settings` bounced
home; the no-home/no-key account rendered "Pick a place to start", "Get set up"
and "At a glance" simultaneously; the no-gallery account rendered the eBird
error card with At a glance and no photo row. Responsive: 390×844, 844×390,
768×1024 and 1280×720 all had `scrollWidth == clientWidth`; inputs/selects 48 px
at 18 px font. Console showed only the two known Google Maps `gmp-pin` /
`gmp-advanced-marker` deprecation warnings.

### Deferred (agreed in the plan, not done here)

Notable-heading wording for non-7-day windows, notable/needs de-duplication,
Activity/Nearest sorting, preserving failed search text in the place input,
Best Places density (Home moved from 6 to Targets' 10, which makes the portrait
page ~10,067 px tall), and restoring the count-rich needs search placeholder.

One judgment call worth a later product review: the species drilldown keeps its
historical 50 km radius on the plain saved-home view, because attaching the
Home context there would have silently narrowed results from 50 km to the saved
40 km. A searched place _does_ pass its origin and radius through. CODEX
accepted the asymmetry as backward-compatible for this release.
