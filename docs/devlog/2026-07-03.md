# 2026-07-03

## Species Detail Count Consistency

### Summary
Fixed `td-d9b004`: species detail pages now show the full set of recent species
reports instead of silently truncating the list to 15 rows.

### Root Cause
The summary rows were already enriched from the species-specific eBird endpoint,
but `/species/[code]` sorted that same merged observation set and then called
`.slice(0, 15)`. For the Common Loon sample from the restored production dump,
the species feed had 65 reports across 65 locations totaling 110 birds, while
the detail page rendered only 15 reports / 15 locations / 25 birds.

### What Changed
- Added a shared `speciesObservationDetails()` helper that keeps every merged
  species observation while adding distance, Google place ID, and verified
  hotspot metadata.
- Updated `/species/[code]` to use that helper and removed the silent 15-row
  cap.
- Added regression coverage to assert that detail rows preserve all reports and
  stay consistent with aggregate location and bird totals.

### Verification
- Restored the July 3 production snapshot into isolated `birds_test` and
  reproduced the Common Loon mismatch there; production data was not modified.
- `npm test` - pass, 9 files / 27 tests
- `npm run check` - pass, 0 errors / 0 warnings
- `npm run build` - pass
- `git diff --check` - pass

### Process Note
Follow `cs.md` assiduously. If a future detail view limits rows for usability,
the UI must say so and provide a way to show more or all rows; silent truncation
contradicts the app's evidence-based debugging and data-integrity rules.
