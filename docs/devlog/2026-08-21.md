### Key Technical Insight
The root cause of 17 missing pins was a single line: `res.json()` on an HTTP 200
empty body. eBird's hotspot/info endpoint returns 200 (not 404) for personal L-ids
with zero bytes. The resulting `SyntaxError` wasn't an `EbirdError`, so it bypassed
the resolver's typed catch — aborting the entire pass silently. Every subsequent
sync hit the same L-id first and crashed the same way, leaving 0 `lifer_loc_attempts`
and 9 real public hotspots behind it unresolved.

The CookieJar domain-awareness fix is a security improvement independent of the
pin fix — the old jar sent ALL cookies to ALL redirect hops, meaning CAS
`JSESSIONID` would have been sent to `ebird.org` and vice versa.

### What Was Done

  CAS gateway bounce (same-host redirect to `/home`). Fixed double "Settings"
  copy (removed "check Settings." from `locError` — template already provides

- **CODEX1 Commits D–G** (`d24983e`..`f21f4b0`): Found the actual root cause
  across several iterations:
  1. eBird checklist JSP serializes coordinates as **quoted strings**
     (`"lat":"30.263"`) not bare numbers — regex needed optional quotes.
  2. Some pages use **ampersand-delimited** coordinates
     (`lat=30.263&lng=-81.637`) — added a third regex fallback.
  3. Login-page detection was too narrow — `"checklistId"` JSON key wasn't
     present. Added `hasChecklistMarker()` that also checks `data-sub-id`
     attributes and `subId` assignments.
  4. Migrations 0026 + 0027 reset `no_coords` attempts to retry with the
     fixed regexes.
  5. Added life-list search feature and filter module.

### Key Technical Insight
Both AI agents wrote coordinate-extraction regex based on **assumed** eBird HTML
structure without ever fetching a real checklist page to inspect it. An
experienced developer's first move would have been to look at the actual page
source. The browser extension was down, but that's no excuse — could have asked
the user for a snippet, curled from prod, or SSHed to check. This is the cs.md
evidence-based debugging mandate applied to parsing: always inspect real data
before writing regex for external system output.
