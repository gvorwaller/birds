### Key Technical Insight
Two lessons from the silent-failure incident: (1) every loop outcome needs
words — the one unrendered state ("stalled") was inevitably the one a real
user hit; (2) in-memory counters that reset on deploy are worse than no
counter, because their behavior is effectively random from the user's side.
Also: retry loops must not re-bill known-bad targets — the cooldown pattern
(15 min for hotspots, mirroring the county 24h cooldown) fixes both the waste
and the loop-slot starvation. And the SPA insight that made
navigation-survival cheap: module-scoped runes state + a fetch-driven action
loop lives above the page tree, so only a hard reload kills it — no worker
needed (yet; Gaylon prophesies background workers are coming).
