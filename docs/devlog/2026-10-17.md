### Key Technical Insight
- **A NOT over a nullable predicate drops rows from both sides.** `NOT (… AND next_retry_at > NOW() …)` is unknown when next_retry_at is NULL, so the row fell out of both "scheduled" and "waiting". Wrap the predicate in `COALESCE(…, false)`.
- **New tables inherit `birds_app=arwd`** from 0002's default privileges. A "read-only" table needs an explicit REVOKE.
- **`sudo` resets the environment.** Pass `PGCONNECT_TIMEOUT` with `sudo -u postgres env PGCONNECT_TIMEOUT=10 psql …`.

### What Was Done

**eBird traffic** (`src/lib/server/ebird-traffic.ts`, migration 0090)
- Every eBird request is counted by day × endpoint × origin × outcome:
  - endpoint: an allow-list name for API paths, web URLs and ebird_cache key prefixes;
  - origin: the running job's type, now carried in the claim context, otherwise worker or web;
  - outcome: ok / not_found / http_error / rate_limited / network_error / cache_hit / stale_fallback.
- Counting points:
  - `ebirdFetch` and `ebirdFetchOrNull`: time and size through the body (`ebirdFetch` now reads text, then `JSON.parse`).
  - `cachedFetch`: hits and stale fallbacks.
  - `fetchWithJar`: redirects and errors are counted at headers; a 2xx is counted once, when its body is read or knowingly discarded.
- Saving: a per-process tally is flushed every 60 s and on clean shutdown (the shutdown waits for a write already in flight). Days are UTC everywhere. Pruned at 400 days.
- Drift guards: a test fails if any eBird path template classifies as "other", or if any cache-key prefix is unmapped.

**Slow pages** (`src/lib/server/page-timing.ts`, migration 0091)
