### Production count-query correction during release

- The first live smoke verified small viewed/search counts but found that
  full Not yet viewed counting exceeded its query deadline. Production plans
  overestimated the geography join and used expensive sorts of intermediate
  species/location rows; direct global grouping also remained too slow.
- Large study lists now reuse the bounded per-country membership query with
  two concurrent reads, then intersect each country's species with the exact
  selected study codes. Small lists retain the species-index query and join
  the real frequency-fetch primary key. Both strategies deduplicate species,
  omit empty countries, and preserve all records. The strategy threshold is
  an execution choice, not a data cap.
- A read-only production benchmark counted all countries in 23.1 seconds
  (slowest individual country: US, 10.4 seconds), within the individual
  15-second read deadline. Counts stream while page controls remain available.
  Added a real-DB parity regression for the large-list strategy; rerun checks
  and final production browser verification are recorded on the td.

## Faster study-country membership (`td-713ca8`, follow-up to `td-81600d`)

- Replaced country-list and country-expansion scans of weekly reports with
  `species_country_membership`, one row per reported country/species. A compact
  per-location species ledger preserves every region, county, and hotspot's
  contribution. Country rows retain a source count so removing one location
  cannot erase reports from another. Taxonomy replacement and retired codes
  remain independent of this summary.
- This behaves like an incrementally maintained materialized view. PostgreSQL
  statement triggers refresh only locations touched by weekly inserts, updates,
  or deletes; location-ledger deltas update the compact country summary in the
  same transaction. Metadata changes remap country membership, parent deletion
  cascades contributions, and owner bulk resets clear summaries. No scheduled
  refresh, provider traffic, per-user cache, or stale-cache window is introduced.
  Triggers also cover the previous worker version during a deployment.
- Migrations 0053–0055 backfill the summary while blocking source writes, then
  install maintenance, FK-compatible same-location refresh locking, and a guard
  against re-truncating tables already cleared by a parent CASCADE. Applied only
  through the migration runner on isolated `birds_test`; production unchanged.
  Country deltas take ordered transaction advisory locks. Refreshes use NO KEY
  UPDATE so concurrent weekly inserts can retain their FK KEY SHARE locks.
- Country counts and source/date coverage now come from one SQL snapshot;
  expanded membership and its coverage also share one snapshot and the same
  normalized country mapping. Actual-account viewed/unviewed/search filtering,
  country-name ordering, complete results, unknown geography, and retry behavior
  remain intact. Reviewed and updated Help and About.
- Full test-snapshot reconciliation against weekly reports: **109,063 distinct
  country/species pairs, zero differences**, including source counts. Local
  compact count SQL: **39–41 ms**; US membership lookup: **0.5 ms**. Authenticated
  WebKit measured **156 ms** from navigation to the full Not yet viewed country
  list appearing. These are local measurements, not production latency claims.
- A rollback-only test copied actual US-FL report rows into an isolated fixture:
  **19,192 weekly rows / 631 species / 39 batches of at most 500**, inserted with
  summary maintenance in **603 ms**. Both weekly-table TRUNCATE and parent
  TRUNCATE CASCADE were verified in rolled-back owner transactions: summaries
  emptied, then all **109,063 pairs** returned on rollback.
- Validation: focused study/history/API/help suite **39 tests passed**; new real
  DB coverage includes weekly/source deduplication, final-source removal,
  unknown/moved/normalized geography, weekly species/location changes, rollback,
  concurrent locations, concurrent direct weekly inserts, and concurrent real
  storeFrequencies replacements. Authenticated WebKit passed at 390/1200px,
  including counts, expansion, search, retry, return context and user isolation,
  with zero page errors. Check: zero errors/warnings. Production build passed.
