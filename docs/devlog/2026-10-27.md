Artsdatabanken's own API page has no terms beyond "an API that can already be accessed".
- **Counties:** Artskart's filter takes the app's old county numbers 1–20 directly, with the old boundaries:
  - for 2024-10-01…2026-09-30, the 19 counties sum to 3,393,596, the same as one query for all 19 (no overlap);

  So the 2024-county mapping, GADM placement and municipality-majority rules of the GBIF connector are all gone.
- **Names, from the Nordland pull** (498 names): 365 two-part names (99.3% of records; two arrive with a trailing space), 59 "subsp." names, 70 genus or family names, and odd forms ("subsp. a/b", "var. domestica"). Each `TaxonId` has exactly one name.
- **App side:**
  - migration 0096: source `artsobs` (store_observers on, region map 1–20), the `observers` chunk kind with staging and published tables, `artsobs-gbif` switched off;
  - contract: `observers` rows (place, rank, observer, days, species, localities, reports), refused unless the source stores observers; `SUBSPECIES` rank for taxon rows;
  - matching: after the exact species name, an eBird `issf`/`form` of the same name matches the species eBird reports it as (Anas crecca carolinensis → Green-winged Teal); a subspecies is never rolled up to its binomial;
  - Admin → Sources shows a load's observer rows.
- **Connector** (`src/connectors/artsobs/`): month slices, pages of 5,000, one request at a time. A slice counts only when every page agrees on the count and the distinct ids equal it (Artskart repeats a few rows per page); a record met in two months re-reads the county.

  - **Known limit, documented:** a delete plus an add in the same month while it is paged keeps the count, so the load may count the deleted report and miss the new one. Caught in my own test trace, not by a test passing.

## External sources Phase 3: show the reports (td-6895f6)

- **Design change while building:** Hotspots & data lists a county only once eBird data for it is loaded, so a panel inside the county rows would never appear for a county eBird hasn't loaded. Instead the page gets its own "Reports from other sources" card. It lists each active source with its loaded, loading and failed regions, and offers the rest in one "Load a region" picker. Everything comes in the page load in five queries, whatever the number of regions.
- **Read side** (`src/lib/server/external-sources/reports.ts`):

- **Job chip:** an external load links to its row on Hotspots & data. The chip is hidden on /forecast pages, so the card shows the user's own load progress live from the jobs poll.
